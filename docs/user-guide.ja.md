# Folirel ユーザーガイド

Folirelは、Android向けのローカルRSS/Atomリーダーです。Feedlyなどから書き出したOPMLファイルで購読先を取り込むと、各サイトのフィードを端末が直接取得して記事を1つの一覧に表示し、元記事をブラウザで開けます。アカウントもサーバーもログインも不要です。

目次: [インストール](#インストール) · [初回起動](#初回起動) · [OPMLの読み込み](#opmlの読み込み) · [フィードURLの追加](#フィードurlの追加) · [日常の操作](#日常の操作) · [カテゴリ](#カテゴリ) · [更新のしくみ](#更新のしくみ) · [HTTPとHTTPS](#httpとhttps) · [購読の管理](#購読の管理) · [設定](#設定) · [データ・バックアップ・アンインストール](#データバックアップアンインストール) · [制限事項](#制限事項) · [トラブルシューティング](#トラブルシューティング)

## インストール

Android 9（API 28）以上が必要です。

1. APKを入手します。プロジェクトのリリースページに配布されていればそこからダウンロードするか、[building.md](building.md) の手順で自分でビルドします。
2. 端末でAPKを開きます。使用したアプリ（ブラウザやファイル管理アプリ）からのインストールを許可するよう求められるので、許可してください。この許可はそのアプリごとの1回だけです。
3. パソコンから入れる場合は、USBデバッグを有効にして `adb install -r app-debug.apk` を実行します。

デバッグビルドを使う場合の注意: デバッグAPKは、ビルドしたパソコンのデバッグ鍵で署名されます。別のパソコンでビルドしたAPKは署名が異なるため、今入っているアプリに上書きインストールできません。いったんアンインストールが必要で、その場合データは消えます。事前にOPMLを書き出してください（[データ・バックアップ・アンインストール](#データバックアップアンインストール)）。

## 初回起動

初回は説明画面（「Folirelへようこそ」）が表示されます。

- 記事は各サイトから直接取得します。
- 購読先は端末に保存します。アカウントは不要です。
- OPMLで移るのは購読先だけです。既読・保存は移りません。
- 「保存」はブックマークです。ページ自体は保存しません。

ここで「2時間ごとに自動更新」（非従量制ネットワークのときのみ。OSの都合で遅れることがあります）をオフにもできます。あとから設定でも変更できます。「スキップ」で先へ進みます。

購読が1件もないときのホーム画面には、「OPMLを読み込む」と「フィードURLを追加」のボタンが出ます。

## OPMLの読み込み

OPMLは購読先を交換するための標準的なファイル形式で、多くのフィードリーダーが書き出せます。

1. 今使っているリーダーでOPMLを書き出し、ファイルを端末に置きます。Feedlyの場合はWeb版のOPMLエクスポートを使います（メニューの場所はFeedly側の仕様なので、見つからないときはFeedlyのヘルプを確認してください）。
2. Folirelのホーム画面の「その他の操作」メニュー（︙）、または「購読管理」画面の同じメニューから「OPMLを読み込む」を開きます。
3. 「ファイルを選ぶ」でOPMLファイルを指定します。この時点ではまだ通信しません。
4. 「取り込み内容の確認」を見ます。新規フィード、購読済み、再購読、新しいカテゴリ、追加するカテゴリ所属、複数カテゴリ所属のフィード、http://のフィード、無効なURL（除外）、非対応の項目（除外）、空のカテゴリ、非標準の構造などの件数が表示されます。
5. 「取り込む」を押します。端末に保存され、フィードの取得が始まります。終わると「取り込み完了」が表示されるので、「記事一覧へ」を押します。

補足:

- 取り込みは追加とマージだけです。既存のフィード・既読・保存した記事は消えません。同じファイルを2回取り込んでも問題ありません。
- OPMLのフォルダはカテゴリになります。複数のフォルダに入っているフィードは、それぞれのカテゴリに属します。
- OPMLに含まれるのは購読先だけです。既読・保存・過去記事、そして書き出したファイルに含まれない項目（FeedlyのBoardsやAI Feedsなど）は移りません。
- 以前に購読解除したフィードがファイルに含まれる場合は、プレビューに名前が表示され、再購読される旨が示されます。
- http://のフィードが含まれると、HTTPSで使えるか確認するダイアログが出ます（[HTTPとHTTPS](#httpとhttps)）。
- ファイルが大きすぎる・項目が多すぎる、XMLが壊れている、OPMLではない、DOCTYPE/エンティティ宣言を含む（安全のため拒否）場合は取り込まれず、何も変更されません。

## フィードURLの追加

「フィードURLを追加」（ホーム画面のメニュー、購読がないときのボタン、「購読管理」の＋ボタン）で、RSSまたはAtomのフィードのアドレスを入力します。サイトのWebページではなく、フィード自体のURLです。ページのアドレスを入れると、取得時に「フィードではありません（HTMLページ）」になります。対応形式はRSS 2.0、Atom 1.0、RSS 1.0（RDF）です。

http://で始まるURLは登録されますが、設定でHTTPを許可するまで取得しません（[HTTPとHTTPS](#httpとhttps)）。

## 日常の操作

### 読む

| やりたいこと | 操作 |
|---|---|
| 元記事を読む | 行をタップします。設定の「記事を開く方法」に従い、アプリ内ブラウザタブ（Custom Tabs）または外部ブラウザで開きます。**開いても既読にはなりません。** |
| 保存（ブックマーク） | 行のブックマークアイコンをタップします。保存した記事は、メニューの「保存した記事」か「保存」フィルタで見られます。 |
| 既読/未読、共有、外部ブラウザ | 行の︙（その他の操作）をタップするか、行を長押しします。メニュー項目は「既読にする」/「未読にする」、「保存」/「保存を解除」、「共有」、「外部ブラウザで開く」です。 |
| リンクのない記事 | タップすると、フィードが提供した概要（「概要を表示」）が表示されます。 |
| まとめて既読 | 「その他の操作」メニューの「この範囲を既読にする」。範囲・条件・検索語・既読になる未読件数がダイアログに表示され、確認するまで何も変わりません。 |
| 先頭へ戻る | スクロール中に現れる「先頭へ戻る」ボタンを使います。 |

既読・未読・保存は、明示的な操作だけで変わります。更新で上書きされることはありません。

### 画面の移動

- **メニュー（ナビゲーション）**: 左上のメニューボタン（「メニューを開く」）で開きます。すべての記事、保存した記事、未分類、カテゴリ（展開可能）、購読管理、設定が入っています。
- **タブとフリック**: 上部のタブに「すべて」「未分類」と各カテゴリが並びます。一覧を左右にフリックして切り替えられます。両端で止まり、循環はしません。タブごとにスクロール位置を覚えます。
- **絞り込みと並び順**: 「すべて」/「未読」/「保存」のチップと、「新しい順」/「古い順」（「その他の操作」メニューにもあります）。
- **検索**: 虫眼鏡アイコンで、現在の範囲内の取得済み記事のタイトル・概要・配信元を検索します。通信はしません。
- **一覧形式**: 「その他の操作」メニューまたは設定で、3種類から選べます。
  - **リスト**: 1列で、見出し・概要・サムネイルを表示します。
  - **リスト（コンパクト）**: 1記事1行の高密度表示です。
  - **マガジン**: 大きさの違うカード（設定で全て同じ大きさにもできます）を、広い画面では最大3列で並べます。

## カテゴリ

カテゴリは任意で、入れ子にできます。

- 「購読管理」を開き、「その他の操作」メニューの「カテゴリ」へ進みます。「カテゴリを作成」「子カテゴリを作成」「名前を変更」「カテゴリを削除」ができます。
- フィードをカテゴリに入れるには、「購読管理」でそのフィードを開き、「カテゴリ」欄でチェックします。1つのフィードを複数のカテゴリに入れられます。
- カテゴリを削除（子カテゴリを含む）しても、フィードと記事は削除されません。所属がなくなったフィードは未分類になります。

## 更新のしくみ

- 一覧を**下に引く**か、「その他の操作」メニューの「更新」で更新します。更新するのは表示中の範囲（すべて、1つのカテゴリ、未分類）だけです。未読・保存・検索の絞り込みで対象が狭まることはありません。
- 従量制ネットワークでは、確認ダイアログ（「従量制ネットワーク」）で今回だけ更新するか（「今回は更新する」）を選びます。
- **自動更新**（設定）はバックグラウンドで、15分・30分・1・2・6・12・24時間ごと、または「オフ」から選べます。既定は2時間ごとです。実行時刻はOSが決め、遅れることがあります。既定では非従量制ネットワークのときだけ実行します（OSの従量制判定に従うもので、厳密なWi-Fi判定ではありません）。
- **アプリを開いたときに更新**（既定でオン）は、アプリを開いたときに更新します。最短30分おきで、回線条件は自動更新と同じです。
- フィードは同時に最大4本（同じサイトは最大2本）、1回の更新につき約6分の時間枠内で取得します。届かなかったフィードは次回に優先されます。時間切れになった定期更新では、未完了のフィードについて短い続行が最大2回行われます。
- サーバーが対応していれば条件付き取得（ETag / Last-Modified）を使うので、変化のないフィードは軽く済みます。失敗したフィードは待ってから自動で再試行し、サーバーが指定した`Retry-After`も守ります。手動更新なら、通常の失敗はすぐに再試行します。
- **結果の帯**: 更新中と更新後は、一覧の上部の帯に進行状況と「12フィード：正常10・失敗1・待機1」のような要約が出ます。通信の問題を「空の成功」として扱うことはありません。更新できなかったフィードがあれば帯にそう表示され、「未完了・失敗を再試行」が出ます。
- **1つのフィード**: 「購読管理」から開いて「このフィードを更新」を使います。通常の更新で変わらないときは「キャッシュを再検証して再取得」を使います。保存済みの検証情報を送らず、途中のキャッシュに再検証を求めます。記事と既読/保存は残ります。配信元やCDNが古い内容を返す場合もあります。
- **フィード詳細**には、最後の更新要求、応答の状態と所要時間、条件付き取得か否か、最後に正常反映した配信文書（文書内の記事数、重複統合後、日時不明、日時範囲、新規/更新の件数）、端末内の記事数、取得できない理由が表示されます。
- 公開日時のない記事は「日時不明」と表示されます。

## HTTPとHTTPS

暗号化されていないhttp://の通信は経路上で盗み見や改ざんをされる可能性があるため、Folirelは慎重に扱います。

- http://のフィードと画像は、設定の「暗号化されていないHTTPのフィード・画像を許可」をオンにするまで**取得しません**（既定はオフ）。該当フィードには「HTTP保留」と表示されます。この設定はアプリ自身のフィード・画像の取得だけに作用します。HTTPSの証明書検証は決して緩めず、端末が信頼するシステムの証明書だけを使います。
- 「HTTPフィードのHTTPS対応を確認」（「購読管理」のメニュー、購読管理の要約、設定にあります）は、各http://フィードをHTTPSで1回取得し、通常の証明書検証を行います。HTTPSで同じRSS/Atomフィードが取得できたものだけをHTTPSへ変更し、記事・カテゴリ・既読/保存はそのままです。確認できなかったものはHTTPのまま残り、理由（例: 「HTTPSでは別のフィードに到達」「証明書/TLSエラー」「タイムアウト（2回）。後で再確認」）が表示されます。この画面を離れても確認はバックグラウンドで続きます。HTTPフィードを含むOPMLを取り込んだ後は、1回の同意でまとめて確認できます。
- 残ったHTTPフィードを許可するかどうかは、設定での別の判断です。
- **http://の記事を開くとき**: まずFolirelが確認します（「暗号化されていないページ」。「今回は開く」かキャンセル）。「今後、http://の記事を開く前に確認しない」にチェックすると確認が出なくなり、設定の「http://の記事を開く前に確認」で戻せます。これはHTTPのフィード・画像の取得許可とは別で、ブラウザ自身の警告も残ります。

## 購読の管理

ナビゲーションメニューから「購読管理」を開きます。

- 画面上部に前回結果の要約（正常・失敗・HTTP保留・待機・未完了）が出ます。絞り込みチップで「失敗」「未取得」「HTTP保留」「再試行待ち」「更新停止中」に絞れます。「購読を検索」でフィード名を探せます。
- フィードをタップすると詳細が開きます。ここで「名前を変更」、「カテゴリ」の選択、「このフィードの取得を停止」（一時停止）のオン/オフ、「このフィードを更新」、「購読解除」ができます。
- **購読解除**は更新を止め、通常の一覧から外します。記事・保存・既読・カテゴリは端末に残り、保存した記事は「保存」から読めます。フィードは「購読解除済み（保存記事は残ります）」の欄に移り、「再購読する」で戻せます。同じURLをもう一度追加しても戻ります。
- **まとめて操作**: 「その他の操作」メニューの「フィードを選択」（またはフィードを長押し）で選び、「選択したN件の購読を解除」を押します。確認画面には各フィードの失敗の種類・HTTPステータス・最終成功が表示され、すでに回復しているフィードは購読したままにします。解除の直後は「元に戻す」が出ます。失敗しただけではサイトが閉鎖したとは言えません。404/410はアドレスの移転でも起こります。
- **移行先を探す**（フィード詳細）: 「サイト内を探す」は、そのフィードのサイトからRSS/Atomのリンクを探し、本物のフィードか確かめて、記事数や登録中のフィードと共通の記事があるかを示します。「フィード名でWeb検索」は、タップしたときだけ端末の検索アプリにフィード名を渡します。見つけたアドレスは貼り付けて「このアドレスを確認」で調べられます。自動では何も選びません。「このアドレスを使う」を押すと確認（「アドレスを変更」）が出て、変更後も記事・カテゴリ・既読/保存は引き継がれます（一部の記事が新着として再び現れることはあります）。それ以外にURLだけを変えることはできず、別のURLを使うときは新しいフィードとして追加します。
- 「購読管理」の「その他の操作」メニューには、ほかに「カテゴリ」「HTTPフィードのHTTPS対応を確認」「未完了・失敗を再試行」「OPMLを読み込む」「OPMLを書き出す」があります。

## 設定

| 区分 | 項目 | 選択肢・補足 |
|---|---|---|
| 表示 | テーマ | システムに従う、ライト、ダーク |
| 表示 | 一覧形式 | リスト、リスト（コンパクト）、マガジン |
| 表示 | マガジンの並べ方 | 大きさ混在（雑誌風）、すべて同じ大きさ |
| 表示 | マガジンの最大列数 | 自動（画面幅と文字サイズに合わせる）、1列、2列、3列。選んだ列数だと見出しが読めないほど狭くなる場合（小さなウィンドウ、大きな文字）は列数を減らします。列数を保つために文字を縮小することはありません |
| 表示 | 文字サイズ | ×0.9、×1.0、×1.15、×1.3 |
| 表示 | サムネイルと配信元アイコンを表示 | 既定はオン。オフのときは、サムネイルも配信元アイコンも取得・表示しません。アイコンはフィード本体か配信元サイトから1フィードにつき一度だけ調べ、外部のファビコンサービスは使いません |
| 記事を開く方法 | 記事を開く方法 | アプリ内ブラウザタブ（Custom Tabs）、外部ブラウザ |
| 記事を開く方法 | http://の記事を開く前に確認 | 既定はオン |
| 更新 | 自動更新 | オフ、15分・30分ごと、1・2（既定）・6・12・24時間ごと |
| 更新 | アプリを開いたときに更新 | 既定はオン。最短30分おき |
| 更新 | 自動更新は非従量制ネットワークのみ | 既定はオン |
| 更新 | 暗号化されていないHTTPのフィード・画像を許可 | 既定はオフ。HTTPのフィードがあるときは、「HTTPフィードのHTTPS対応を確認」への入口が表示されます |
| データ | 端末に残す記事の目安 | 上限なし（既定）、約1,000・3,000・5,000・10,000・30,000件。下記参照 |
| データ | 画像キャッシュの上限 | 64・128（既定）・256・512MB。次回の起動時に反映します。「画像キャッシュを削除」で消えるのはサムネイルのキャッシュだけです |
| データ | OPMLを書き出す | 購読一覧とカテゴリのみ |
| アプリ情報 | バージョン、ビルド、ライセンス概要 | バージョン、バージョンコード、ビルド識別子が表示されます |

「データ」区分には、保存中の記事数とデータベース容量も表示され、データベースが100MBを超えると警告が出ます。

**端末に残す記事の目安**は取得件数の上限ではなく、フィードが返した記事はすべて保存します。件数を選ぶと、削除される古い既読・非保存の記事の件数が表示され、確認後に削除します。以後も更新後に同じ整理が行われます。未読と保存した記事は削除しません。削除した記事がフィードから再配信されても、未読としては戻りません。

## データ・バックアップ・アンインストール

- すべてのデータ（購読、カテゴリ、記事、既読・保存、設定）は端末内のアプリ専用領域にだけ保存されます。フィードURLに個人用トークンが含まれることがあるため、Androidの自動バックアップと端末間の移行は意図的に無効にしています。
- **アプリをアンインストールするか、Androidの設定でアプリのストレージを消去すると、すべて消えます。**
- **「OPMLを書き出す」**（「購読管理」または設定の「データ」）は、購読一覧とカテゴリを選んだ場所のファイルに保存します。これが唯一のバックアップです。既読・保存や記事は含まれません。フィードURLに個人用トークンが含まれる場合があるので、ファイルは他人に渡さないでください。
- 新しい端末へ移るには、OPMLを書き出し、ファイルをコピーして、新しい端末で読み込みます。既読・保存は引き継がれません。
- アプリをデータを保ったまま更新するには、同じアプリケーションIDと同じ署名鍵のAPKが必要です。デバッグビルドについては[インストール](#インストール)を参照してください。

## 制限事項

- 本文を表示するリーダー、全文抽出、ページのオフライン保存、通知、ウィジェット、読み上げ、端末間の同期はありません。記事は元のサイトで読みます。
- 利用できるのは、フィードが現在返している範囲だけです。アーカイブやページを巡回して過去記事を集めることはしません。
- 1つの配信文書は約5MiB・2,000件までです。超えると「上限超過（サイズ/件数）」で失敗します。OPMLファイルも5MiBまでです。
- 対応するフィード形式はRSS 2.0、Atom 1.0、RSS 1.0（RDF）です。それ以外（JSON Feedなど）には対応していません。
- バックグラウンド更新の時刻は目安で、OSの省電力の仕組みに左右されます。
- 古いAndroid（Android 9など）では、ルート証明書が古いために一部のサイトへのHTTPS接続に失敗することがあります。Folirelはこれを避けるために証明書検証を緩めることはしません。
- 表示言語はシステムの言語に従います。端末が日本語なら日本語、それ以外は英語です。Android 13 以降では、システム設定（設定 > アプリ > Folirel > 言語）でアプリ別の言語も選べます。アプリ内に言語の切り替え項目はありません。

## トラブルシューティング

| 表示 | 意味と対処 |
|---|---|
| 取り込み後に記事が出ない | 初回取得（「フィードを取得中…」）を待つか、下に引いて更新します。一覧上部の帯と「購読管理」の要約で失敗がないか確認してください。 |
| 「HTTP保留」/「HTTPが設定で許可されていません」 | フィードがhttp://です。「HTTPフィードのHTTPS対応を確認」を実行するか、設定でHTTPを許可します。 |
| 「フィードではありません（HTMLページ）」 | アドレスがWebページです。サイトのRSS/Atomフィードのアドレスを調べるか、フィード詳細の「移行先を探す」を使います。 |
| 「見つかりません（404）」/「フィード廃止（410）」 | アドレスが移転したか、フィードが廃止された可能性があります。「移行先を探す」を試すか、購読を解除します。 |
| 「アクセス拒否（401/403）」 | サーバーが要求を拒否しています。ログインが必要な非公開フィードは読めません。 |
| 「アクセス制限中（429）」/「サーバーエラー（5xx）」/「タイムアウト」/「通信エラー」 | たいていは一時的です。後で自動的に再試行します。早く試すには「未完了・失敗を再試行」を使います。サーバー指定の待機は守ります。 |
| 「証明書エラー」 | サイトのHTTPS証明書を検証できません（期限切れ、名前の不一致、未知の発行元、古い端末のルート証明書など）。Folirelはこれを回避しません。 |
| 「フィードの形式エラー（XML）」/「非対応のフィード形式」 | 配信文書が正しいRSS/Atomではありません。こちら側でできることはありません。サイトの運営者に伝えるか、別のフィードアドレスを使ってください。 |
| 「上限超過（サイズ/件数）」 | フィードが上記の上限を超えています。 |
| 「安全のため拒否」 | アドレス（またはリダイレクト先）が、Folirelが接続しない先（ローカルやプライベートネットワークのアドレスなど）を指しています。Folirelが接続するのは公開インターネットのアドレスだけです。 |
| 「保存できません（空き容量を確認）」 | 端末の空き容量が不足しています。空きを作ってください。 |
| 更新しても変わらない | そのフィードで「キャッシュを再検証して再取得」を使います。サイトやCDNが古い内容を返している場合もあります。 |
| 帯に「前回の更新は中断されました」、またはフィードの結果が「未取得（時間切れ）」 | 更新が途中で止まりました。届かなかったフィードは次回優先されます。「未完了・失敗を再試行」でもやり直せます。 |
| 自動更新が遅い | Androidがバックグラウンド処理を遅らせることがあります（バッテリーセーバー、Doze）。更新を定期的にしたいときは、アプリのバッテリー使用を制限なしにし、「アプリを開いたときに更新」をオンにしておきます。 |
| 更新版をインストールできない | 入っているアプリと異なる鍵で署名されたAPKです。[インストール](#インストール)を参照してください。 |
| 「このリンクを開けるアプリがありません。」 | ブラウザをインストール/有効化するか、「記事を開く方法」をもう一方に切り替えます。 |
