# Folirel ユーザーガイド

Folirelは、Android向けのローカルRSS/Atomリーダーです。Feedlyなどから書き出したOPMLファイルで購読を読み込むと、各サイトのフィードを端末が直接取得して記事を1つの一覧に表示し、元記事をブラウザで開けます。アカウントもサーバーもログインも不要です。

## インストール

Android 9（API 28）以上が必要です。APKはプロジェクトの [GitHub Releases](https://github.com/yuu-biz/folirel/releases) から入手します。

1. スマートフォンで、最新リリースのAPKをダウンロードします。
2. ダウンロードしたファイルを開きます。「不明なアプリのインストール」が許可されていないと表示されたら、「設定」を押し、使っているブラウザやファイル管理アプリで「この提供元のアプリを許可」をオンにして戻ります。
3. 「インストール」を押します。

APKがプロジェクトの配布したものか確かめるには、Android SDKのビルドツールがあるパソコンで署名証明書を確認します。

```sh
apksigner verify --print-certs folirel.apk
```

`Signer #1 certificate SHA-256 digest` の行が `<RELEASE_CERT_SHA256>` と一致することを確かめてください。一致しないファイルはインストールしないでください。

**0.x版からの移行。** 1.0より前の版は開発用の鍵で署名されているため、1.0を上書きインストールできません。古いアプリでFolirelのバックアップを作成し（設定 > 保存とデータ > 「Folirelのバックアップを作成」）、アンインストールしてから1.0をインストールし、バックアップを復元します（設定 > 保存とデータ > 「Folirelのバックアップから復元」）。アンインストール前にバックアップを確かめる方法を含む手順は、[Full backup and restore の7節](backup-format.md#7-moving-to-a-differently-signed-app-release-signing)（英語）にあります。0.10.0より前の版には完全バックアップがないため、OPMLを書き出してください（購読とカテゴリだけが移ります）。

## 初回起動

初回は説明画面（「Folirelへようこそ」）が表示されます。

- 購読は端末に保存します。アカウントは不要です。
- 記事は各サイトから直接取得します。
- 「保存」はブックマークです。ページ自体は保存しません。
- OPMLで移るのは購読だけです。既読・保存は移りません。

ここで「2時間ごとに自動更新」（従量制ではないネットワークのときだけ。Androidの都合で遅れることがあります）をオフにもできます。あとから設定でも変更できます。「スキップ」で先へ進みます。

購読が1件もないときのホーム画面には、「OPMLを読み込む」と「フィードURLを追加」のボタンが出ます。

## OPMLの読み込み

OPMLは購読を交換するための標準的なファイル形式で、多くのフィードリーダーが書き出せます。

1. 今使っているリーダーでOPMLを書き出し、ファイルを端末に置きます。Feedlyの場合はWeb版のOPMLの書き出しを使います（メニューの場所はFeedly側で決まるので、見つからないときはFeedlyのヘルプを確認してください）。
2. Folirelのホーム画面の「その他の操作」メニュー（︙）、または「購読管理」画面の同じメニューから「OPMLを読み込む」を開きます。
3. 「ファイルを選ぶ」でOPMLファイルを指定します。この時点ではまだ通信しません。
4. 「読み込む内容」を確認します。新規フィード、購読済み、再購読、新しいカテゴリ、追加するカテゴリ所属、複数カテゴリ所属のフィード、http://のフィード、無効なURL（除外）、非対応の項目（除外）、空のカテゴリ、非標準の構造などの件数が表示されます。
5. 「読み込む」を押します。端末に保存され、フィードの取得が始まります。終わると「読み込み完了」が表示されるので、「記事一覧へ」を押します。

補足:

- 読み込みは追加とマージだけです。既存のフィード・既読・保存した記事は消えません。同じファイルを2回読み込んでも問題ありません。
- OPMLのフォルダはカテゴリになります。複数のフォルダに入っているフィードは、それぞれのカテゴリに入ります。
- OPMLに含まれるのは購読だけです。既読・保存・過去の記事、そして書き出したファイルに含まれない項目（FeedlyのBoardsやAI Feedsなど）は移りません。
- 以前に購読を解除したフィードがファイルに含まれる場合は、プレビューに名前が表示され、再購読されることが示されます。
- http://のフィードが含まれると、HTTPSで使えるか確認するダイアログが出ます（[HTTPとHTTPS](#httpとhttps)）。
- ファイルが大きすぎる・項目が多すぎる、XMLが壊れている、OPMLではない、DOCTYPEやエンティティの宣言を含む（安全のため拒否）場合は読み込まれず、何も変更されません。

## フィードURLの追加

「フィードURLを追加」（ホーム画面のメニュー、購読がないときのボタン、「購読管理」の＋ボタン）で、フィードのアドレス、または読みたいサイトやページのアドレスを入力し、「追加」を押します。対応形式はRSS 2.0、Atom 1.0、RSS 1.0（RDF）、JSON Feed 1.0・1.1です。

- アドレスがフィードなら、すぐに追加します。
- Webページなら、そのページが示すフィードを探し（示していないときは、同じサイトのトップページを1回だけ見ます）、本物のフィードか確かめて一覧にします。購読したいものの「購読する」を押します。押すまでは何も追加しません。[共有から購読](#ほかのアプリから購読共有から購読)と同じ探し方です。
- 見つからないときや読み込めないときは、理由を表示します。「キャンセル」か「OK」で入力したアドレスに戻るので、直してから試せます。
- `https://` は省略できます（例: `example.com`）。
- `http://` のアドレスは、設定でHTTPを許可するまで確かめません（[HTTPとHTTPS](#httpとhttps)）。その間はその旨を表示し、何も送信せず、何も追加しません。

## ほかのアプリから購読（共有から購読）

ブラウザなどのアプリで、ページやリンクを **Folirel** に共有します（テキストの共有先に表示されます）。Folirelは共有されたテキストからアドレスを取り出します。アドレスが1つなら、そこでフィードを探します。アドレス自体がフィードの場合や、ページがフィードを示している場合に、それぞれが本物のフィードか確かめます。テキストに複数のアドレスがあるときは、調べるものを選びます。

- 共有しただけでは何も追加されません。見つかったもの（タイトル、アドレス、記事数、最新の日付）がダイアログに表示されます。「購読する」で追加し、「キャンセル」か戻るで何も変えずに閉じます。ページに複数のフィードがあるときは1つを選びます。
- すでに購読しているフィードなら、そう表示され、「フィードの詳細」を開けます。以前に購読を解除したフィードなら「再購読する」が出て、記事・既読・保存・カテゴリが元のとおり戻ります。
- フィードはカテゴリなしで追加されます。カテゴリはフィードの詳細で変えます。`http://` のアドレスもHTTPの設定に従います。HTTPがオフの間は、その旨を表示して何も送信しません。
- 共有されたページ（記事など）がフィードを示していないときは、同じサイトのトップページを1回だけ見て、そこで示されているフィードを探します。見つかったものには「サイトのトップページで見つかりました」と表示されます。それより深くは探さず、アドレスを推測したりWeb検索したりもしません。それでも見つからないときはその旨を表示するので、フィードのアドレスを自分で調べて「フィードURLを追加」を使ってください。
- 初回起動の説明を終える前に共有した場合は、説明が終わってから処理されます。

## 日常の操作

### 読む

| やりたいこと | 操作 |
|---|---|
| 元記事を読む | 行をタップします。設定の「記事を開く方法」に従い、アプリ内タブ（Custom Tabs）または外部ブラウザで開きます。**開いても既読にはなりません。** |
| 保存（ブックマーク） | 行のブックマークアイコンをタップします。保存した記事は、「表示と絞り込み」（検索の隣のボタン）の「保存」で見られます。メニューは見る場所を選ぶだけなので、カテゴリを変えても「保存」は選ばれたままです。 |
| 既読/未読、共有、外部ブラウザ | 行の︙（その他の操作）をタップするか、行を長押しします。メニュー項目は「既読にする」/「未読にする」、「保存」/「保存を解除」、「共有」、「外部ブラウザで開く」です。続けて「このフィードの記事を表示」（そのフィードの記事だけの一覧にします。既読・保存は変わらず、戻るで元の画面に戻ります）と「フィードの詳細」（アドレス・状態・一時停止の画面）があります。 |
| 行をスワイプ | 「リスト」と「リスト（コンパクト）」では、設定で「スワイプ操作」をオンにすると、行を右にスワイプして既読・未読、左にスワイプして保存・保存の解除を切り替えられます（左右は入れ替えられます）。行は元の位置に戻ります。指を離すと切り替わる位置まで来ると軽く振動し、それより短いスワイプでは何も変わりません。切り替えで一覧に合わなくなった記事（「未読」の表示中に既読にした記事など）は一覧から消え、「元に戻す」が出ます。オンの間は、カテゴリをタブで切り替えます。カードにはスワイプ操作はありません。 |
| リンクのない記事 | タップすると「この記事にはリンクがありません」と表示されます。フィードが提供した概要は、行を長押しするか、︙メニューの「概要を表示」で読めます。 |
| まとめて既読 | 「その他の操作」メニューの「すべて既読にする」。対象・表示する記事・期間・検索語・非表示キーワード適用の有無・既読になる未読件数がダイアログに表示されます。一覧に見えている記事だけが対象で、確認するまで何も変わりません。 |
| 先頭へ戻る | スクロール中に現れる「先頭へ戻る」ボタンを使います。 |

既読・未読・保存は、明示的な操作だけで変わります。更新で上書きされることはありません。

### 画面の移動

- **メニュー（ナビゲーション）**: 左上のメニューボタン（「メニューを開く」）で開きます。見る場所を選びます。すべての記事、未分類、カテゴリ（展開可能）、購読管理、設定が入っています。
- **タブとスワイプ**: 上部のタブに「すべて」「未分類」、ピン留めしたカテゴリ、そのほかのカテゴリが並びます。一覧を左右にスワイプして切り替えられます（「リスト」「リスト（コンパクト）」で「スワイプ操作」がオンのときは、記事の上のスワイプはその記事の操作になるので、タブで切り替えます）。タブの列は指の動きについてきて、両端で止まり、循環はしません。タブごとにスクロール位置を覚えます。タブの列だけを横に動かしてタブを探すこともでき、その場合はカテゴリは変わりません。
- **カテゴリへ移動**: 上部のカテゴリ名（小さな矢印付き）を押します。一覧からカテゴリを選ぶか、名前や親カテゴリの名前の一部を入力して検索します。各行のピンのボタンで、そのカテゴリをタブの先頭にピン留めできます。
- **表示と絞り込み**: 検索の隣のボタンで「表示と絞り込み」を開きます。「すべて」/「未読」/「保存」、期間（「すべて」「24時間」「3日」「7日」「30日」。現在からさかのぼります。記事は削除されません）、非表示キーワード、「新しい順」/「古い順」、レイアウトがあります。カテゴリ名の下の小さな行に、表示する記事・期間・並び順が表示されます。
- **非表示キーワード**: 「表示と絞り込み」の「管理」で語を追加します（最大32語、1語64文字まで）。タイトルまたは概要にその語を含む記事は、どのカテゴリでも「保存」でも一覧に出ません。非表示は既読でも削除でもありません。フィルタをオフにするか語を削除すれば、既読・保存の状態のまま再び表示されます。有効なときは表示ボタンに小さな点が付きます。
- **検索**: 虫眼鏡アイコンで、現在の範囲内の取得済み記事のタイトル・概要・フィード名を検索します。通信はしません。
- **レイアウト**: 「表示と絞り込み」（開いているカテゴリのレイアウト。「すべて」では全体の標準）または設定（すべてのカテゴリの標準）で、5種類から選べます。
  - **リスト**: 1列で、見出し・概要・サムネイルを表示します。
  - **リスト（コンパクト）**: 1記事1行の高密度表示です。
  - **マガジン**: 大きさの違うカード（設定ですべて同じ大きさにもできます）を、広い画面では最大5列で並べます（列数はウィンドウの幅と文字の大きさで決まります）。
  - **段違い（Masonry）**: 高さの違うカードをレーンに並べます（スマートフォンでは2レーン）。
  - **タイル（Bento）**: 大きさの違うタイル（小・横長・縦長・大）を隙間なく敷き詰めます。

## カテゴリ

カテゴリは任意で、入れ子にできます。

- 「購読管理」を開き、「その他の操作」メニューの「カテゴリ」へ進みます。「カテゴリを作成」「子カテゴリを作成」「名前を変更」「カテゴリを削除」ができます。
- フィードをカテゴリに入れるには、「購読管理」でそのフィードを開き、「カテゴリ」欄でチェックします。1つのフィードを複数のカテゴリに入れられます。
- カテゴリを削除（子カテゴリを含む）しても、フィードと記事は削除されません。所属がなくなったフィードは未分類になります。
- **タブの順序**: 「その他の操作」メニューの「カテゴリ・タブを整理」（またはカテゴリ一覧の下の同じボタン）を開きます。ピン留めしたカテゴリは先頭に並びます。ハンドルをドラッグするか、行のメニューの「上へ移動」/「下へ移動」で順序を変えます。「標準の並び順に戻す」で戻るのは順序だけで、ピン留めとカテゴリごとの表示設定はそのままです。変わるのはタブの順序だけで、どのカテゴリにどのフィードが入っているかは変わりません。
- **カテゴリごとの表示**: そのカテゴリを開いた状態で「表示と絞り込み」を使うと、そのカテゴリのレイアウトだけが変わります（最初の選択肢「標準を使う」は設定に従います）。「並べ方と列数…」で、そのカテゴリのマガジンの並べ方と最大列数を決められます。「このカテゴリの表示をリセット」で、この3つを標準に戻します。

## 更新のしくみ

- 一覧を**下に引く**か、「その他の操作」メニューの「更新」で更新します。更新するのは表示中の範囲（すべて、1つのカテゴリ、未分類）だけです。「未読」「保存」や検索で対象が狭まることはありません。
- 従量制ネットワークでは、確認ダイアログ（「従量制ネットワーク」）で今回だけ更新するか（「今回は更新する」）を選びます。「今後、従量制ネットワークでも確認しない」にチェックすると、以後は確認なしで更新します。設定の「従量制ネットワークで更新する前に確認」で確認を戻せます。
- **自動更新**（設定）はバックグラウンドで、15分・30分・1・2・6・12・24時間ごと、または「オフ」から選べます。既定は2時間ごとです。実行時刻はAndroidが決め、遅れることがあります。既定では従量制ではないネットワーク（通常はWi-Fi）のときだけ実行します。従量制かどうかはAndroidの設定に従います。
- **アプリを開いたときに更新**（既定でオン）は、アプリを開いたときに更新します。最短30分おきで、ネットワークの条件は自動更新と同じです。
- フィードは同時に最大4本（同じサイトは最大2本）、1回の更新につき約6分の時間内で取得します。届かなかったフィードは次回に先に取得します。時間切れになった自動更新では、未完了のフィードについて短い続きの処理が最大2回行われます。
- サーバーが対応していれば、フィードが変わったかどうかをサーバーに確かめる取得（ETag / Last-Modified）を使うので、変化のないフィードは軽く済みます。失敗したフィードは待ってから自動で再試行し、サーバーが指定した`Retry-After`も守ります。手動更新なら、通常の失敗はすぐに再試行します。
- **結果のお知らせ**: 更新中と更新後は、一覧の上に進行状況と「12フィード: 正常10・失敗1・待機1」のような要約が出ます。通信の問題を「空の成功」として扱うことはありません。更新できなかったフィードがあればそう表示され、「未完了・失敗を再試行」が出ます。
- **1つのフィード**: 「購読管理」から開いて「このフィードを更新」を使います。通常の更新で変わらないときは「強制的に更新」を使います。変更の確認を使わずにフィードを取り直します。記事と既読の状態はそのままです。サイトやCDNが古い内容を返す場合もあります。
- **フィードの詳細**には、最後の更新要求、応答（HTTPのステータスコード）と所要時間、条件付き取得か否か、最後に成功した取得（文書内の記事数、重複統合後、日時不明、日時の範囲、新規・変更の件数）、端末内の記事数、取得できない理由が表示されます。
- 公開日時のない記事は「日時不明」と表示されます。

## HTTPとHTTPS

暗号化されていないhttp://の通信は、途中で盗み見や改ざんをされるおそれがあるため、Folirelは慎重に扱います。

- http://のフィードと画像は、設定の「暗号化されていないHTTPのフィード・画像を許可」をオンにするまで**取得しません**（既定はオフ）。該当フィードには「HTTP未許可」と表示されます。この設定はFolirel自身のフィード・画像の取得だけに作用し、ブラウザには影響しません。HTTPSの証明書の検証は決して緩めず、端末が信頼するシステムの証明書だけを使います。
- 「HTTPフィードのHTTPS対応を確認」（「購読管理」のメニュー、購読管理の要約、設定にあります）は、各http://フィードをHTTPSで1回ずつ取得し、通常どおり証明書を検証します。HTTPSで同じRSS/Atomフィードが取得できたものだけをHTTPSに切り替え、記事・カテゴリ・既読・保存はそのままです。確認できなかったものはHTTPのまま残り、理由（例: 「HTTPSでは別のフィードに到達」「証明書エラー」「2回タイムアウト。後で再確認」）が表示されます。この画面を離れても確認はバックグラウンドで続きます。HTTPフィードを含むOPMLを読み込んだ後は、1回の同意でまとめて確認できます。
- 残ったHTTPフィードを許可するかどうかは、設定での別の判断です。
- **http://の記事を開くとき**: まずFolirelが確認します（「暗号化されていないページ」。「今回は開く」かキャンセル）。「今後、http://の記事を開く前に確認しない」にチェックすると確認が出なくなり、「http://の記事を開く前に確認」（設定 > 記事を開く方法）で戻せます。これはHTTPのフィード・画像の取得の設定とは別で、ブラウザ自身の警告も残ります。

## 購読の管理

ナビゲーションメニューから「購読管理」を開きます。

- 画面上部に前回の結果の要約（例: 「40フィード: 正常37・失敗2・HTTP未許可1」）が出ます。0件の項目は表示しません。絞り込みチップで「失敗」「未取得」「HTTP未許可」「再試行待ち」「一時停止中」に絞れます。「購読を検索」でフィード名を探せます。
- フィードをタップすると詳細が開きます。ここで「名前を変更」、「カテゴリ」の選択、「このフィードを一時停止」のオン/オフ、「このフィードを更新」、「購読を解除」ができます。
- **購読の解除**では、そのフィードの更新と一覧への表示をやめます。記事・保存・既読・カテゴリは端末に残り、保存した記事は「保存」から読めます。フィードは「購読解除済み（保存記事は残ります）」の欄に移り、「再購読する」で戻せます。同じURLをもう一度追加しても戻ります。
- **まとめて操作**: 「その他の操作」メニューの「フィードを選択」（またはフィードを長押し）で選び、「選択したN件の購読を解除」を押します。確認画面には各フィードの失敗の種類・連続失敗の回数・最終成功が表示され、すでに回復しているフィードは購読したままにします。解除の直後は「元に戻す」が出ます。失敗していても、サイトがなくなったとは限りません。フィードが移転しただけのこともあります。
- **移行先を探す**（フィードの詳細）: 「サイト内を探す」は、そのフィードのサイトからRSS/Atomのリンクを探し、本物のフィードか確かめて、記事数や今のフィードと共通の記事があるかを示します。「フィード名でWeb検索」は、タップしたときだけ検索アプリにフィード名を渡します。見つけたアドレスは貼り付けて「このURLを確認」で調べられます。自動では何も選びません。「このアドレスを使う」を押すと確認（「アドレスを変更」）が出て、変更後も記事・カテゴリ・既読・保存はそのままです（一部の記事が新着として再び表示されることはあります）。フィードのアドレスを変える方法はこれだけです。それ以外で別のURLを使うときは、新しいフィードとして追加します。
- 「購読管理」の「その他の操作」メニューには、ほかに「カテゴリ」「HTTPフィードのHTTPS対応を確認」「未完了・失敗を再試行」「OPMLを読み込む」「OPMLを書き出す」があります。

## データ・バックアップ・アンインストール

- すべてのデータ（購読、カテゴリ、記事、既読・保存、設定）は端末内のアプリ専用領域にだけ保存されます。フィードURLに個人用トークンが含まれることがあるため、Androidの自動バックアップと端末間の移行は意図的に無効にしています。
- **アプリをアンインストールするか、Androidの設定でアプリのストレージを消去すると、すべて消えます。**
- **「Folirelのバックアップを作成」**（設定 > 保存とデータ）は、すべてを1つのファイルに保存します。購読（アドレスの変更履歴を含む）、カテゴリ（並び順・ピン留め・レイアウト）、端末に保持している記事、既読・保存の状態、すべての設定（カスタムの色を含む）が入ります。フィードのアイコンと画像キャッシュは含まれません（Folirelがあとで取得し直します）。ファイルは暗号化されず、フィードURLに個人用トークンが含まれる場合があるので、他人に渡さないでください。
- **「Folirelのバックアップから復元」**（同じページ）は、まずバックアップの内容と現在端末にあるものを表示し、確認するまで何も変更しません。復元すると、現在のFolirelのデータはすべてバックアップの内容に**置き換わります**（統合はしません）。復元の途中で問題が起きても、データと設定は元のままです。復元中はフィードを取得せず、次回の更新で通常どおり取得します。
- **「購読リストを書き出す（OPML）」**（「購読管理」または設定 > 保存とデータ）は、ほかのリーダーでも読める形式で購読とカテゴリだけを保存します。既読・保存、記事、設定は含まれません。OPMLの読み込みは追加とマージだけを行います。
- 新しい端末へ移るとき、または別の署名鍵のFolirel（新規インストールが必要）へ移るときは、Folirelのバックアップを作成し、ファイルをコピーして、新しい端末でFolirelをインストールしてから復元します。詳細: [Full backup and restore](backup-format.md)（英語）。
- 新しい版を上書きインストールすれば、データはそのまま残ります。それには同じアプリケーションIDと同じ署名鍵のAPKが必要です。[インストール](#インストール)を参照してください。

## 制限事項

- 本文を表示するリーダー、全文抽出、ページのオフライン保存、通知、ウィジェット、読み上げ、端末間の同期はありません。記事は元のサイトで読みます。
- 利用できるのは、フィードが現在返している範囲だけです。アーカイブやページを巡回して過去の記事を集めることはしません。
- 1つのフィードの文書は約5MiB・2,000件までです。超えると「サイズか件数が上限を超過」で失敗します。OPMLファイルも5MiBまでです。
- 対応するフィード形式はRSS 2.0、Atom 1.0、RSS 1.0（RDF）、JSON Feed 1.0・1.1です。それ以外（Atom 0.3や、サイト独自のJSON APIなど）には対応していません。
- 自動更新の時刻は目安で、Androidの省電力の仕組みに左右されます。
- 古いAndroid（Android 9など）では、ルート証明書が古いために一部のサイトへのHTTPS接続に失敗することがあります。Folirelはこれを避けるために証明書の検証を緩めることはしません。
- 表示言語はシステムの言語に従います。端末が日本語なら日本語、それ以外は英語です。Android 13 以降では、システム設定（設定 > アプリ > Folirel > 言語）でアプリ別の言語も選べます。アプリ内に言語の切り替え項目はありません。
